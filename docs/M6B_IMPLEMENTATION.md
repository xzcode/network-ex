# M6 follow-up: multi-profile daemon, DNS hub, selective IPv4 exit (2026-11-26)

Version 0.6.1-dev-m6. Linux core integration tests passed. Not a general-purpose full-tunnel VPN; native desktop and full Internet exit remain pending.

## Multi-profile daemon
One daemon supports 1–8 fixed local profile slots (-profiles, default 8). Slot 0 preserves the prior root/device and settings.json layout. Other slots use service-owned profile-N directories, separate identity/WireGuard keys, persistent desired state, interface and UDP port (base port + slot). Additional Windows/Linux interfaces use nex-pN, Darwin uses auto-selected utun. Setup preflight and route installation are serialized within the process. Each profile may connect/disconnect/forget independently; no arbitrary paths through IPC. The existing requests default to slot 0; list returns summaries, status/enroll/connect/disconnect/forget accept a bounded integer slot. Administrator gateway and exit flags apply to the default slot only. Vue sidebar lists enrolled networks and allows choosing a free slot. Native Rust command schema updated; frontend build verified, native Tauri not built.

## Private DNS
With daemon -dns-listen 127.0.0.1:15353, a single TCP/UDP loopback DNS listener serves current authorized records from each active profile. Use label.p0.network-ex.internal, label.p1.network-ex.internal, etc. The short name label.network-ex.internal resolves only if exactly one currently valid profile contains the label; ambiguity returns SERVFAIL. Profile-qualified names never cross into another profile. TTL <=5 seconds, capped by authorization expiry. The view is cleared on disconnect, reconfiguration, terminal error and authorization expiry; refresh requires a fresh running TUN status. External DNS queries refused. Standalone managed-run retains its own listener. 
Optional OS split DNS integration: deploy/dns/split-dns.sh print|install|remove dnsmasq|macos [port]. It generates a domain-scoped dnsmasq include or macOS /etc/resolver/network-ex.internal file, refuses overwrite/removal of differing configuration, does not modify global nameservers or automatically reload services. Linux requires an active dnsmasq configuration including /etc/dnsmasq.d; administrator explicitly reloads and checks it. macOS requires admin installation and scutil --dns verification. Script syntax/render/port checks passed; actual OS resolver installation and macOS/Windows resolver runtime are NOT RUN. No automatic system DNS integration claimed.

## Selective IPv4 exit (Linux)
Schema v4 stores a single administrator-approved exit grant per client, pointing to an approved gateway in the same network with up to eight exact public IPv4 targets. GET/PUT /api/v1/networks/{id}/exit, administrator only. Existing device-pair ACL must permit the pair. Reject default route, RFC1918, link-local, loopback, documentation/reserved ranges, multicast and exit chaining. Device revocation deletes grants; pair ACL deny suppresses them. Network revision changes invalidate earlier leases. Old agents without ExitRoutes capability receive HTTP 426 when exit grants are enabled. No device can be forced to become an exit gateway by central configuration alone.
Example administrative grant body (replace IDs and destination with authorized values):
```json
{"client":"client-device-id","gateway":"gateway-device-id","targets":["93.184.216.34"]}
```
An empty targets list withdraws a grant. Client administrator explicitly opts in: managed-run (or default daemon profile) -exit-via GATEWAY_DEVICE_ID -exit-targets IP[,IP]. Gateway administrator explicitly opts in with -allow-exit-targets IP[,IP]. Only intersection of grant and local allowlist is applied. The gateway requires admin-enabled IPv4 forwarding and a physical unicast route to each target; external NAT/return routing remains an administrator responsibility. No programmatic NAT or global forwarding changes. Static JSON tunnel mode rejects exit options; managed authorization required. WireGuard AllowedIPs adds only exact /32 destination routes, with per-peer served scope on the gateway. TUN guard permits only client-initiated TCP/UDP/ICMP Echo and tracked replies for exit traffic, respecting pair service ACL. No public default route capture, no exit chaining. Existing route collision/underlay endpoint checks and ICE candidate exclusions apply.
Client installs a dedicated nftables inet table nexexit_<interface> with a narrowly scoped output rule blocking selected destination IPv4 traffic unless sent through that interface, before activating managed exit. It does not alter other IPv4 destinations or IPv6. Missing nftables or unsupported platform fails startup. On a gracefully canceled run, the program removes only its own table; terminal unexpected error or hard kill retains the protection table to avoid fallback, requiring explicit administrator inspection and cleanup before reconnection. Grant withdrawal or route removal while managed-run remains running does not release the filter. This is selected-target local-output protection, not a global kill switch, not a full privacy VPN, and not a guarantee against root-admin network manipulation or arbitrary later firewall changes. For recovery after verifying the old agent is stopped, root inspects nft list table inet nexexit_nex0 and may explicitly delete that table if it is the Network EX-owned table. No global firewall flushing. 
Web management exposes exit grant edit/withdraw; JS syntax checked. Local opt-in remains an administrative CLI/service startup decision, not a remote setting.

Reproduce from Linux checkout with TUN, iproute2, iptables, nftables, unshare/nsenter, Python3, openssl and root in a test environment:
```sh
mkdir -p bin
go build -o bin/network-ex-server ./cmd/server
CGO_ENABLED=0 go build -o bin/network-ex-agent ./cmd/agent
sudo bash scripts/m6b-multiprofile.sh outside "$(pwd)/bin"
sudo bash scripts/m6b-exit.sh outside "$(pwd)/bin"
```
