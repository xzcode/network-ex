# 中继服务

## 原则
Relay 转发 WireGuard 密文，不终止用户隧道，不做任意互联网代理；单个 flow 连接已授权设备对。优先 TLS WSS（二进制消息，M1 可验证 TCP/UDP 封锁场景），QUIC datagram 在 M2/M5 验证后启用，避免过早维护两条不成熟实现。STUN 独立 UDP listener，参考 RFC8489，限制请求/响应速率，不提供开放 TURN。中继不能保证不掌握通信元数据。

## 注册与授权
节点首次使用短期单次 enrollment token（从受限文件/stdin 读取，避免进程列表与 shell history）；生成节点身份、管理方校验 scope、颁发短期证书或签名凭据；节点以 mTLS 或签名 challenge 向控制面续期，独立撤销。
租约由控制面签发，绑定 node_id、tenant/network、src/dst device ID、flow、expiry、limits、nonce；两端均需证明持有各自身份私钥，验证当前成员状态，Relay 验签并校验目的设备已连且同 flow；禁止仅靠可转发 bearer token 冒用身份。M1 测试可用离线签发测试 lease 及预置公钥，不关闭认证。到期停止转发，不因控制面失联无限续期；节点撤销或策略变更推送，失联最多租约期限。
有界队列、max frame、max flows、每设备/组织/节点 bytes/s 与总流量配额；慢连接背压或丢弃，连接异常关闭；防重放、连接洪泛、跨租户转发与放大。指标不含 payload。中继流量口径入口/出口分别统计，不重复算成计费出口。

## 多节点调度
节点类型 official/private/org，community 后续审批；权限过滤 -> 双端可达交集 -> 负载与容量过滤 -> RTT 合计、丢包、成本、地区限制评分。默认同一 relay 传输两端，不做节点级 mesh；客户端保存多个可用节点，故障换节点须取得对应授权，drain 停新连接并迁移旧 flow。节点目录 revision + TTL，客户端可缓存但不能超期授权。心跳初始 15s，45s 标记不可用，待压测。
## 运营
节点加入/下线无需重启管理服务。独立可执行模式、无业务数据库密码、可观测健康；支持私有及组织节点，不允许未审批共享中继。按出口容量水平扩容；准确测量峰值、协议开销、带宽计费，禁止宣称未测吞吐。
